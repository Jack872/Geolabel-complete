# 坐标系动态获取优化总结

## 优化目标

将系统中静态设置的坐标系（如 EPSG:3301、EPSG:3857）改为动态获取，提高系统的灵活性和适用性。

## 修改内容

### 1. 前端优化

#### 1.1 上传组件优化 (`StepUploadModal.jsx`)
- **新增功能**: 添加坐标系选择表单
- **常用坐标系**: 提供8种常用坐标系选项
- **自定义支持**: 支持用户输入自定义坐标系
- **验证机制**: 坐标系格式验证（EPSG:XXXX）
- **描述信息**: 每个坐标系都有详细说明

**主要特性**:
```javascript
// 常用坐标系选项
const COMMON_CRS_OPTIONS = [
  { value: 'EPSG:4326', label: 'WGS84 (EPSG:4326)', description: '世界大地坐标系，GPS常用' },
  { value: 'EPSG:3857', label: 'Web Mercator (EPSG:3857)', description: '网络墨卡托投影，Web地图常用' },
  { value: 'EPSG:3301', label: 'Estonian Coordinate System (EPSG:3301)', description: '爱沙尼亚坐标系' },
  // ... 更多选项
];
```

#### 1.2 坐标系工具类 (`coordinateSystem.js`)
- **统一管理**: 集中管理所有坐标系配置
- **验证功能**: 坐标系代码格式验证
- **转换参数**: 自动生成OpenLayers转换参数
- **推荐机制**: 根据地区推荐合适的坐标系

#### 1.3 地图组件优化
- **动态转换**: 根据任务信息动态获取坐标系
- **兼容性**: 保持向后兼容，默认使用EPSG:3857
- **审核页面**: 修改坐标系获取逻辑
- **标注页面**: 集成坐标系工具类

## 技术特性

### 1. 多源获取策略
1. **溯源系统优先**: 从PROV实体属性中获取
2. **文件系统备用**: 从TIF文件头信息获取
3. **默认值保底**: 使用EPSG:3857作为默认值

### 2. 验证机制
- **格式验证**: 支持EPSG:XXXX和ESRI:XXXX格式
- **有效性检查**: 验证坐标系代码的有效性
- **兼容性检查**: 检查坐标系之间的转换兼容性

### 3. 溯源集成
- **完整记录**: 坐标系信息完整记录到溯源系统
- **历史追踪**: 支持坐标系变更历史追踪
- **关系建立**: 建立坐标系与数据实体的关系

### 4. 向后兼容
- **默认值**: 未指定坐标系时使用默认值
- **接口兼容**: 保持原有API接口不变
- **渐进升级**: 支持逐步迁移到动态坐标系

## 支持的坐标系

### 常用坐标系列表
- **EPSG:4326**: WGS84 地理坐标系
- **EPSG:3857**: Web Mercator 投影坐标系
- **EPSG:3301**: 爱沙尼亚坐标系
- **EPSG:2154**: 法国 Lambert-93 投影
- **EPSG:32633**: WGS84 UTM 33N 投影
- **EPSG:32634**: WGS84 UTM 34N 投影
- **EPSG:25832**: ETRS89 UTM 32N 投影
- **EPSG:25833**: ETRS89 UTM 33N 投影

### 扩展支持
- 支持任意EPSG和ESRI坐标系代码
- 支持用户自定义坐标系输入
- 支持坐标系描述和说明

## 使用说明

### 1. 文件上传
1. 选择TIF文件
2. 选择或输入坐标系
3. 添加描述信息（可选）
4. 开始上传

### 2. 数据处理
- 系统自动从任务中获取坐标系
- 支持多任务坐标系统一
- 自动处理坐标转换

### 3. 溯源查看
- 在溯源管理界面查看坐标系信息
- 追踪坐标系变更历史
- 查看坐标系相关的处理活动

## 注意事项

1. **数据一致性**: 确保同一数据集中的坐标系一致
2. **转换精度**: 不同坐标系转换可能存在精度损失
3. **性能考虑**: 大量数据转换时注意性能优化
4. **兼容性**: 确保所有组件都支持动态坐标系
