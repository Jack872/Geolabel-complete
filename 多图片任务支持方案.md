# 多图片任务支持实现方案

## 方案概述：任务组模式（推荐）

### 核心思路
保持现有的 Task-Server 一对一架构不变，通过引入"任务组"概念实现多图片支持。

### 实现步骤

#### 1. 数据库层面（最小改动）

**新增字段到Task表：**
```sql
ALTER TABLE task ADD COLUMN task_group_id VARCHAR(50) NULL COMMENT '任务组ID，同组任务共享相同的group_id';
ALTER TABLE task ADD COLUMN group_sequence INT DEFAULT 1 COMMENT '在任务组中的序号';
ALTER TABLE task ADD COLUMN is_group_master TINYINT(1) DEFAULT 1 COMMENT '是否为主任务（1=主任务，0=子任务）';
```

**优势：**
- 不破坏现有表结构
- 现有代码无需大幅修改
- 向后兼容（单图片任务group_id为NULL）

**2.2 修改TaskController**
```java
@PostMapping("/publishMultiImageTask")
public Result publishMultiImageTask(@RequestBody Map<String, Object> map) {
    // 获取多个服务器ID
    List<String> serverIds = (List<String>) map.get("serverIds");
    String groupId = UUID.randomUUID().toString();
    
    // 创建主任务（第一个图片）
    int masterTaskId = taskService.createTask(dateRangeStr, taskName, taskType, 
                                            serverIds.get(0), creatorUserId, taskClass);
    taskService.updateTaskGroup(masterTaskId, groupId, 1, true);
    
    // 创建子任务（其他图片）
    for (int i = 1; i < serverIds.size(); i++) {
        int subTaskId = taskService.createTask(dateRangeStr, taskName + "_" + (i+1), 
                                             taskType, serverIds.get(i), creatorUserId, taskClass);
        taskService.updateTaskGroup(subTaskId, groupId, i+1, false);
    }
    
    // 只为主任务分配用户（子任务继承主任务的分配）
    // ... 现有的用户分配逻辑
}

@GetMapping("/getTaskGroup/{taskId}")
public Result getTaskGroup(@PathVariable Integer taskId) {
    Task task = taskService.selectTaskById(taskId);
    if (task.getTaskGroupId() != null) {
        List<Task> groupTasks = taskService.getTasksByGroupId(task.getTaskGroupId());
        return ResultGenerator.getSuccessResult(groupTasks);
    }
    return ResultGenerator.getSuccessResult(Arrays.asList(task));
}
```

**3.2 标注页面修改**
```jsx
// 新增状态管理
const [taskGroup, setTaskGroup] = useState([]);
const [currentTaskIndex, setCurrentTaskIndex] = useState(0);
const [currentTask, setCurrentTask] = useState(null);

// 获取任务组信息
useEffect(() => {
  const fetchTaskGroup = async () => {
    const taskId = getTaskId;
    const result = await request(`/wegismarkapi/task/getTaskGroup/${taskId}`);
    if (result.code === 200) {
      setTaskGroup(result.data);
      setCurrentTask(result.data[0]);
    }
  };
  fetchTaskGroup();
}, []);

// 切换图片函数
const switchToTask = (index) => {
  if (index >= 0 && index < taskGroup.length) {
    setCurrentTaskIndex(index);
    setCurrentTask(taskGroup[index]);
    // 重新加载地图
    loadMapForTask(taskGroup[index]);
  }
};

// 快捷键支持
useEffect(() => {
  const handleKeyPress = (e) => {
    if (e.key === 'ArrowLeft') {
      switchToTask(currentTaskIndex - 1);
    } else if (e.key === 'ArrowRight') {
      switchToTask(currentTaskIndex + 1);
    }
  };
  
  window.addEventListener('keydown', handleKeyPress);
  return () => window.removeEventListener('keydown', handleKeyPress);
}, [currentTaskIndex, taskGroup]);
```

### 方案优势

1. **最小改动**：
   - 只需在Task表添加3个字段
   - 现有的一对一关系保持不变
   - 现有业务逻辑基本不需要修改

2. **向后兼容**：
   - 单图片任务继续正常工作
   - 现有任务不受影响

3. **扩展性好**：
   - 支持任意数量的图片
   - 可以轻松添加任务组级别的操作

4. **用户体验**：
   - 支持键盘快捷键切换
   - 左侧文件列表直观显示
   - 保持每张图片的独立标注状态

### 实现工作量评估

- **后端**：2-3天（添加字段、修改Service、Controller）
- **前端**：3-4天（UI组件、状态管理、交互逻辑）
- **测试**：1-2天

**总计：6-9天**

这个方案既满足了多图片需求，又最大程度保持了现有架构的稳定性。
